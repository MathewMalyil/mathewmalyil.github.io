Important Security Notice - Version 1.0.2

We have identified a security limitation affecting contact verification in the currently published version of Malakh (version 1.0.2).

Matching verification emojis do not reliably confirm the identity of the person or device you are communicating with.

Different identities and communication sessions may produce the same verification symbols. We have also identified limitations in how verification approvals and trusted contact information are associated with active communication sessions.

As a result, a nearby active attacker could potentially impersonate a contact during connection establishment. Encryption alone does not eliminate this identity-verification risk.

Until these issues are corrected and validated, users should not rely on matching emojis or existing trusted contact indicators as conclusive proof of identity. We recommend avoiding sensitive or confidential communications through this version of Malakh.

We are working on security improvements. No particular incident of unauthorized message interception has been established by our investigation to date. This notice does not promise a specific security-update release date.

1. Overview

Malakh is an offline nearby communication application. Its core messaging operates directly between nearby devices without requiring an internet connection or a developer-operated central messaging server.

This policy describes how Malakh handles information, its technical security measures, and the known limitations affecting the currently published version.

2. Data Handling and Messaging

  • No Accounts: Malakh does not require user accounts, phone numbers, or email sign-ins.
  • No Central Servers: The developer does not operate a central messaging server that receives users' messages, peer identities, or contacts.
  • No Analytics or Ads: The currently published application contains no advertising SDKs, tracking pixels, or analytics trackers.
  • Local Content Storage: User-created message content is stored locally on the sender and recipient devices in Android-protected application storage.
  • Peer Communication: Messages are transmitted directly between nearby devices using Bluetooth Low Energy (BLE). Communication involves exchanging the protocol and identity information necessary to establish a connection.
  • Recipient Device Autonomy: Information delivered to another user's device is controlled independently by that device's user.
  • Support Communications: If you contact us by email, we receive the email address and information you voluntarily provide in that communication. Please do not send private cryptographic keys or sensitive conversation contents in support requests.

3. Security and Authentication

  • Message Encryption: Malakh uses authenticated encryption mechanisms to protect message content during established encrypted peer sessions. This does not independently guarantee that the intended recipient has been correctly authenticated.
  • Session Establishment: Connection establishment exchanges cryptographic identity and handshake information needed for nearby communication.
  • Emoji Verification Limitation: Version 1.0.2 displays a Short Authentication String (SAS) using emojis. We have identified that these displayed symbols are not reliably bound to the complete authenticated identity and session information. Matching emojis must therefore not be treated as reliable proof of the other party's identity or as assurance against interception.
  • Trusted Contact Limitations: The currently published version has known limitations concerning how verification approval and stored trust are associated with specific sessions. A trusted or verified status should not be treated as an absolute security guarantee.
  • Public Identifiers: Public identity information and cryptographic public-key information may be exchanged between devices during communication.
  • Private Keys: Private identity-key material is intended to remain in Android-protected storage on the user's device and is not transmitted to a developer-operated messaging server.
  • Security Limitations: No communication application can guarantee absolute protection. Users should consider the known verification limitations described in the security notice above when deciding what information to share.

4. Device Permissions

  • Bluetooth Permissions: Nearby Bluetooth permissions (Scan, Connect, Advertise) are used for peer discovery, advertising, connection, and direct communication.
  • Legacy Location Requirement: On Android 11 (API level 30) and earlier, Android may require Location permission for Bluetooth LE scanning. Malakh uses BLE scan results to discover nearby peer radios and does not use these results to derive, record, or retain physical location.
  • Unrequested Permissions: The currently published Malakh application does not request contacts, microphone, camera, or shared external media storage permissions for its core messaging functionality.

5. Retention and Data Deletion

  • Data Retention: Local information remains in protected application storage until removed.
  • Deletion Controls: Data can be cleared locally through Android system settings by clearing Malakh's application data, or by uninstalling the application.
  • Deletion Consequences: Clearing application data may permanently remove locally stored messages, identity information, trusted contact records, and other application information.
  • Recipient Copies: Clearing local information does not remove copies of messages previously delivered to another user's device.
  • No Central Message Deletion: Because the developer does not operate a central message database, the developer cannot remotely delete messages independently stored on another user's device.
  • Support Data Requests: For questions about personal information voluntarily provided through support communications, contact malyilmathew@gmail.com .
  • No Data Sales: No Malakh user data is sold or provided to advertisers, analytics companies, or data brokers.

6. Security Measures and Children's Privacy

  • Technical Security: Malakh uses cryptographic and device-local protection mechanisms. These measures do not eliminate the identified contact-verification and trust-authorization limitations in version 1.0.2.
  • Security Improvements: Identified vulnerabilities are being evaluated for correction and validation. Any future security improvements apply only when incorporated into an installed application version.
  • Children's Privacy: Malakh is a general communication application and is not specifically directed to children. Parents and guardians should consider the security limitations described in this policy.

7. Updates and Contact

Changes will be reflected by updating the revision date at the top of this page. Updating this document does not, by itself, change the security characteristics of previously installed Malakh versions.
